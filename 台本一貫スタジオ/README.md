# 🧬 台本一貫スタジオ

参考台本の「型」を抜き、チャンネルのコンセプトとキャラクターを立て、企画から執筆・自動検品・添削学習までを
**このPCの中だけ**で回すローカルツールです。外部サーバーには何も送りません。
AIエンジンにはお使いの **Claude Code** を使います（追加のAPI料金はかかりません）。

## 必要なもの

1. **Python 3.10以上** — https://www.python.org/ （インストール時に「Add to PATH」にチェック）
2. **Claude Code** — ターミナルで `claude` が使える状態（ログイン済み）

## 起動

**Claude Code をお使いの方**: 解凍したフォルダを Claude Code で開き、「台本スタジオを立ち上げて」と言ってください。同梱の CLAUDE.md の指示で、Python と Flask の確認、起動、ブラウザの表示、最初の手順の案内まで Claude Code が行います。

**手動で起動する方**:

`start.bat` をダブルクリック → ブラウザで http://localhost:5071 が開きます。
右上の「接続テスト」で Claude Code とつながることを確認してください。

## 流れ（7ステップ）

| STEP | やること | 裏で動くもの |
|---|---|---|
| 1 参考台本 | 真似したい台本を1〜6本貼る。伸びなかった台本は「失敗例」に切替。作りたいネタ・方向性があれば先に書く（任意） | 成功例だけから型を抽出。ネタは診断・設計のすべてに前提として渡り、STEP 4 のテーマ欄に自動で入る |
| 2 型の分析 | 型テーブルを確認。「診断」でジャンル・必要な設計・用意する素材を判定し、提案どおり一括で作るか質問に答える | 分析結果と診断はチャンネルカルテに保存 |
| 3 チャンネル設計 | コンセプト・キャラクター・世界設定（時代背景・経緯・複数人物・相関図・プロット）を作る。手直しはJSON欄で | 出口逆算のコンセプト・6軸採点、キャラ14項目、世界設定の整合点はすべて検品項目になる |
| 4 企画と設計図 | テーマ（ネタから自動入力）で設計図を作る。設計と合わなければ「設計を再考」で柱とプロットだけ更新。足りない情報はディープリサーチ用プロンプトで調べ、結果を貼る | 設計図にはコンセプト・キャラ・世界設定・固有ルールが毎回注入される |
| 5 執筆と検品 | 執筆ボタン1つで、執筆→検品→不合格のブロックだけ修正→差分再検品→日本語推敲まで自動 | 検品官（型・キャラ・世界設定の整合・固有ルール・逐語引用の機械照合）＋冒頭30秒レビュー＋参考台本との口調・語彙照合＋機械コピーチェック＋日本語推敲。合格したブロックは書き換えず、変わったブロックだけ再照合・再推敲する。任意でJev外部採点 |
| 6 添削と学習 | 右側で台本を手直しし「差分から学習」を押す | 差分から書き方ルールを抽出し、カルテの固有ルールへ。次回の執筆・修正・検品に自動で効く |
| 7 完了 | 成功台本としてカルテに登録。台本は `projects/<ID>/台本.txt` にも出力 | 成功台本は文体見本として次回の修正に使われる |

2本目からは、ホームのカルテで「この型で新作」を押してネタを入力すると、分析と設計を飛ばして STEP 4 の企画から始められます。
10本ほど回すと固有ルールが貯まり、手直しがほぼ要らない初稿に育っていきます。

## 予算主義（AI利用枠＝トークンの使い方）

AIへの入力を「仕様」と「参照」に分け、仕様は全文、参照は予算内の抜粋で渡します。変わっていないブロックは再処理しません。

- **仕様＝全文で渡す**：設計図、コンセプト・キャラ・世界設定の設計書、固有ルール、貼り付けた素材、直す対象のブロック、検品チェックリスト。
- **参照＝予算内の抜粋**：参考台本（執筆する位置に対応する部分＋分析から機械的にまとめた「声カード」）、成功台本の文体見本（最新1本の抜粋）、既に書いた本文（直前の末尾＋各ブロックの要点）、推敲の前後文脈（前の塊の末尾と次の塊の冒頭）。
- **変わっていない所は再処理しない**：検品で不合格になったブロックだけを書き直し、口調照合は変わったブロックだけ、冒頭レビューは冒頭が変わった時だけ、推敲は変わったブロックだけ。合格したブロックは触らないので、書き直しによる退行も起きません。
- **1回の入力に上限**（既定3.6万字）を設け、超えそうなときは参照から順に縮めます。仕様だけで超える場合は結果画面に警告を出します。
- **消費の見える化**：各ジョブの呼び出し回数・入力/出力トークン（Claude Code の応答から実測。取れなければ概算）を STEP 5 の結果とホームの一覧に表示し、プロジェクトにも記録します。1回の呼び出しには Claude Code 自身のシステムプロンプト（約1.6万トークン）が必ず載るため、呼び出し回数そのものも減らしています。

目安（参考台本3本×7,000字・12ブロック約1万字・成功台本3本蓄積のベンチ）：執筆から推敲まで1本で、入力 約94万字 → 約36万字、呼び出し29回 → 18回。修正リストで2項目直す操作は 約34万字 → 約8万字。

`python check_inputs.py` で、直近のプロジェクトについて「仕様が全文で入っているか」「参照が予算内か」「各呼び出しが上限以内か」「ナレッジが欠けていないか」を機械確認できます。旧方式（参考台本を全文で渡す）は設定で戻せます。

なお、macOS で作られた配布 zip ではファイル名の正規化（NFD）のせいで、Windows/Linux で `knowledge/` の5本（冒頭30秒レビュー・コンセプト正本・コンセプト雛形・話し言葉仕上げ・具体化レシピ）と `manual/はじめに.md` が読めず、無言で空のまま注入されていました。この版では名前の違いを無視して読むようにしたため、その環境では修正前よりコンセプト設計・冒頭レビュー・推敲の入力が増えます（欠けていた基準が入るためで、品質は上がります）。

## データの場所（すべてこのフォルダ内）

- `karte/` … チャンネルカルテ（型・コンセプト・キャラ・固有ルール・成功台本・文体見本）。1チャンネル1ファイル
- `projects/` … プロジェクト（参考台本・設計図・台本・検品結果・添削差分）
- `knowledge/` … 各工程のプロンプトに注入される資料。編集すると次の実行から反映されます（画面右上「同梱ナレッジ」で閲覧）
- `manual/manual.md` … 台本の考え方マニュアル（画面右上「台本の考え方」）

## 設定（画面右上「⚙ 設定」または settings.json）

- `engine`：`claude`（本番）／`mock`（画面テスト用のダミー応答）
- `audit_rounds`：自動検品で不合格を直す回数の上限（既定2）
- `tone_check`：参考台本と口調・語彙を照合する（既定オン）
- `auto_polish`：検品合格後に日本語推敲を自動で行う（既定オン）
- `ref_mode`：執筆に渡す参考台本。`budget`＝予算内・位置対応の抜粋（既定・推奨）／`full`＝全文（旧方式・高コスト）／`excerpt`＝冒頭と中盤だけ（最軽量）
- `ref_budget_chars`：参考台本の合計字数（既定6,000。成功例で分け合う。1本1,500字に足りなければ長い3本だけ使う）
- `input_cap_chars`：1回の呼び出しの入力上限（既定36,000字）
- `write_chunk_chars` / `max_blocks_per_chunk`：1回で書くブロックの目安字数（2,400）と上限数（4）。1ブロックずつ書きたいときは `max_blocks_per_chunk` を1に（0は既定値扱い）
- `ref_mode: full` は参考台本の渡し方だけを旧方式（全文）に戻します。全文の書き直し・全塊の再推敲は復元しません（意図的）
- `polish_chunk_chars`：推敲の1回あたり字数（3,600。推敲はナレッジ約1.4万字が毎回載るので回数を減らしている）
- `prev_text_cap`（2,500）／`style_sample_cap`（3,000）／`tone_ref_chars`（4,500）／`context_chars`（800）／`polish_context_chars`（600）：各参照の抜粋字数
- `jev.enabled`：外部採点 Jev を検品に加える（任意）。使うには Node 22、`jev` フォルダで `npm install`、APIキーを `~/.config/jev/key.txt` に保存。無くても検品は動きます

## うまく動かないとき

- **接続テストが失敗する** → ターミナルで `claude` と打って起動するか確認。起動しないなら Claude Code を再インストール
- **画面が真っ白／起動しない** → `start.bat` の黒い窓のエラーを確認。多くは Python 未インストールか Flask 導入失敗
- **検品が毎回同じ項目で落ちる** → STEP 3 の固有ルールに、その項目の直し方を1行足してください（検品と修正の両方に効きます）
- **キャラの口調がずれる** → STEP 3 のキャラ設定で「言わないこと」「口癖」「文末」を具体的にすると検品項目になります
- **AI利用枠（トークン）がすぐ尽きる** → 結果画面の「今回のAI利用」で、どの工程が重いかを確認。素材が約8,000字を超えると、執筆・検品官・部分修正（不足時の字数調整）の各呼び出しに全文で入るので絞る（推敲・口調照合・冒頭レビューには入りません）。参考台本の合計や入力上限は設定で下げられます。「再検品だけ」は採点のみで修正も推敲もしません
- **参考台本の声が写らないと感じる** → 設定の「参考台本の渡し方」を「全文」に戻して比べてください（コストは数倍になります）。STEP 6 の添削を数本回すと固有ルールで声が安定します
