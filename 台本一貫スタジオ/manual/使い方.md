# 台本一貫スタジオ 使い方マニュアル

このツールは、参考台本の「型」を抜き、チャンネルのコンセプトとキャラクターを立て、企画から執筆・自動検品・日本語推敲・添削学習までを、あなたのPCの中だけで回します。外部サーバーには何も送りません。AIはお使いの Claude Code を使うので、追加のAPI料金はかかりません。

## 準備（最初の1回だけ）

1. Python 3.10以上をインストールする（インストール時に「Add to PATH」にチェック）。
2. Claude Code をインストールし、ターミナルで `claude` と打って起動することを確認する。
3. `start.bat` をダブルクリックする。ブラウザで http://localhost:5071 が開く。
4. 画面右上の「接続テスト」を押し、「接続OK」と出れば準備完了。

## 全体の流れ

| STEP | 画面でやること | 裏で動くこと |
|---|---|---|
| 1 参考台本 | 真似したい台本を貼る（1〜6本）。作りたいネタ・方向性があれば先に書く（任意） | 成功例だけから型を抜く。ネタは以降の全設計に前提として渡る |
| 2 型の分析 | 型テーブルを確認し、真似たくない型の✔を外す | 型をカルテに保存 |
| 3 チャンネル設計 | コンセプトとキャラクターを設計する | 設計書をカルテに保存し、以降の全工程に注入 |
| 4 企画と設計図 | テーマを決めて設計図を作る。足りない情報を調べて貼る | 設計図にコンセプト・キャラ・固有ルールを反映 |
| 5 執筆と検品 | 執筆ボタンを押して待つ | 執筆→検品→修正→再検品→日本語推敲まで自動 |
| 6 添削と学習 | 台本を手直しして「差分から学習」を押す | 修正パターンを固有ルールとしてカルテに蓄積 |
| 7 完了 | 成功台本として保存 | 台本ファイルを出力し、文体見本として登録 |

1本目は STEP 1 から。2本目以降は、ホームのカルテで「この型で新作」を押し、ネタを入力すると、設計済みのチャンネルは STEP 4 の企画から始まります（STEP 3 は確認画面として残り、変更がなければ触らなくて大丈夫です）。

## STEP 1 参考台本を入れる

- 台本か動画の文字起こしを貼ります。ファイル選択やフォルダ読み込みもできます。
- 各カードの「成功例／失敗例」を選びます。失敗例に切り替えた台本は、型の抽出から外され、その構成は真似しません。
- 成功例が3本以上あると型の精度が上がります。
- 「カルテ」欄で既存のカルテを選ぶと、分析を飛ばして進みます。
- **作りたいネタ・企画の方向性**（任意）：ここに書くと、診断の提案、コンセプトの柱、キャラの背景、世界設定のプロットがそのネタを前提に作られ、STEP 4 のテーマ欄にも自動で入ります。後からテーマを変えても、STEP 4 の「設計を再考」で柱とプロットだけ更新できるので、設計をやり直す必要はありません。

## STEP 2 型を確認する

- 型テーブルは「新作でも守るルール」です。真似たくない行は✔を外してください。
- 自由度テーブルは「変えてよいところ」です。
- 弱い型（根拠が薄いもの）は補足メモに出ます。

### 診断（STEP 2 の下）

「診断する」を押すと、参考台本からジャンル・形式・視聴者を判定し、次の5つについて「必須／推奨／任意」と理由を出します。

- チャンネル設計（コンセプト）
- キャラクター設定
- 世界設定（複数人物・物語・時代背景がある場合）
- 素材（本人の実績・実例など、本人しか持っていないもの）
- 調査（数字・制度・史実など、調べれば分かるもの）

こちらで作れるものは「提案」として案を出し、本人しか答えられないことだけ質問します。回答欄に書いて「提案どおり一括で作る」を押すと、コンセプト→キャラクター→世界設定まで自動で作って STEP 3 に進みます。自分で調整したい場合は「提案をメモ欄に入れる」を押してから、STEP 3 で個別に作ります。用意すべき素材の一覧と、事前調査のプロンプトもここで出ます。

## STEP 3 チャンネル設計

### コンセプト

メモ欄に、出口（最終的に売るもの・つなげたいもの）、対象、やりたいことを書いて「コンセプトを設計する」を押します。出口から逆算して、集める層、前提認識、約束、柱、前に出す1つ、世界観、ギャップの種、6軸の採点が出ます。

- 致命傷が出たら、メモを直して再設計するか、JSON欄で該当箇所を直して「手直しを保存」を押します。
- 6軸で△や×が付いた軸は、理由を読んで判断してください。無理に◎にする必要はありません。

### キャラクター

メモ欄に、実在の人物か架空か、年齢、口調、外見の希望などを書いて「キャラクターを設計する」を押します。人格、背景、価値観、ギャップ、沸点、話し方、言わないこと、セリフ見本、外見8項目が出ます。

- 「言わないこと」「口癖」「文末」「沸点」は、そのまま検品項目になります。具体的に書くほど検品が効きます。
- 実在の人物の場合、背景に事実でないことが入っていたらJSON欄で直してください。

### 世界設定（時代背景・経緯・登場人物・相関図・プロット）

会話劇、物語仕立て、歴史再現、複数の人物が出る台本、時代背景がある題材で使います。一人語りの解説だけなら省略できます。

メモ欄に時代・舞台・登場人物・出来事・その状況になった経緯を書いて「世界設定を作る」を押すと、次が1枚になります。

- 時代・舞台・その状況に至った背景と、物語が始まる時点の状況
- 世界の前提（制度、お金の流れ、人間関係の常識）
- 登場人物（主人公を含む複数人）。それぞれの性格、価値観、欲しいもの、恐れ、一人称・文末・口癖、言わないこと
- 相関図。関係、互いに抱く感情、互いの呼び方、火種
- プロット。あらすじと、起承転結の順に並んだ出来事、各場面の目的と感情、明かす情報、やってはいけない展開
- 整合点。時系列、誰が誰を何と呼ぶか、誰が何を知っているか

ここに書いた呼び方・関係・出来事の順番・整合点は、そのまま検品項目になります。Jevを使う場合は、相関図との矛盾、時代背景との矛盾、プロット順の逸脱、価値観との矛盾が数値でも採点されます。

### 固有ルール

STEP 6 の添削から学習したルールがここに貯まります。不要なルールは✕で消せます。手で足したいルールは、STEP 6 の「添削の意図」欄に書くとそのまま登録されます。

## STEP 4 企画と設計図

1. テーマを入力します。決まらないときは「おまかせ提案」を押すと、型とコンセプトに合う企画が出ます。
2. 「設計図を作る」を押します。ブロック構成、文字数、感情曲線、使う型が表になります。作成後に自動で設計図の検品が走り、ネタ・ターゲット・目的・要望・コンセプトの出口と柱・キャラの口調と沸点・世界設定のプロット順が反映されているかを10項目で判定します。不合格があれば1回だけ自動で直し、結果は表の上に「反映度」と内訳で出ます。Jevを使う場合は外部採点も付きます。
   - チャンネル設計（コンセプト・キャラ）が無いまま STEP 4 に来ると警告が出ます。設計図はネタと型だけで作られてしまうので、「STEP 2 の診断から一括で作る」を押してから設計図を作り直してください。
3. 「足りない情報と調査」を確認します。
   - あなたしか知らない情報（体験談、実績、数字）は、貼り付け欄に書きます。
   - 調べれば分かる情報は、ディープリサーチ用プロンプトをコピーし、お使いのAIの調査機能に貼って、結果を貼り付け欄に入れます。
   - 貼り付け欄の内容だけが「事実」として台本に使われます。空欄でも執筆できますが、不確かな箇所は要確認マーカー付きになります。
4. 設計図を直したいときは、修正指示欄に書いて「設計図を修正」を押します。台本を書き直すより、ここで直すほうが速いです。
   - テーマがチャンネル設計（柱・プロット）と合わないときは「このテーマで設計を再考」を押します。出口・キャラ・相関図はそのままで、コンセプトの柱と世界設定のプロットだけをテーマ前提で更新します。
5. 「この設計図で執筆」を押します。
   - **外部AI（Gemini 等のブラウザ画面）に書かせたい場合**は、代わりに「外部AI用の執筆パックを書き出す」を押します。ツールが Claude Code に渡しているものと同じ材料（型・設計図・コンセプト・キャラ・世界設定・固有ルール・素材・声の見本・執筆規範）を、ブロックごとの指示文にしてクリップボードとファイルに書き出します。1ブロックずつ貼って書かせ、返ってきた本文を「■ブロック名」の形式でまとめて、STEP 5 の「外部AIの出力を取り込む」に貼ると、Claude Code で書いた場合と同じ検品・修正・推敲の輪が走ります。 参考台本を全文含むため1ブロックの指示文は8万字前後になります。Gemini のブラウザ画面は1回の貼り付けに上限があるので、長い場合は前半と後半に分けて貼ってから送信してください。

## STEP 5 執筆と検品

執筆ボタンを押すと、次の順で自動で進みます。

1. 執筆（型・設計図・コンセプト・キャラ・固有ルール・素材を使う）。設計図のブロックを1つずつ、直前までに書いた本文を文脈として渡しながら順に書きます（長い台本を一度に書かせると後半が薄くなるため）。各ブロックの執筆時にも参考台本は全文（成功例・合計4万字まで）を渡し、リズム・話題の転換・CTAの温度を写させます。設定で「抜粋だけ」にも、旧方式の一括執筆にも戻せます
2. 機械コピーチェック（参考台本と連続20文字以上一致する表現を検出し、あれば自動で書き直す）
3. 検品官による採点（型の遵守、キャラの口調・言わないこと・沸点・価値観、世界設定との整合（時代背景・相関図の呼び方と関係・プロットの順番・整合点）、固有ルール、事実の規律、日本語の癖）。判定には本文からの逐語引用が必須で、引用が本文に無い不合格は無効票として捨てます。
4. 冒頭30秒レビュー（100点満点。70点未満は不合格扱い）
5. 口調・語彙の照合。参考台本の抜粋と新作を比べ、一人称・文末・口癖・語彙の温度・リズム・ジャンル特有の言い回しのズレを逐語で指摘します（内容の違いは見ません。表現のコピーはさせません）。ズレは不合格として修正の輪に入ります。設定で切れます
6. 不合格項目だけを修正し、再検品（回数上限は設定で変更。既定2回）。修正のたびに各ブロックの字数を設計図の目安と機械照合し、±25%を外れたブロックだけを字数指定つきで1回書き直します
7. 日本語推敲（意味・事実・キャラの声を変えずに、耳で聞いて一度で入る日本語へ。主述のねじれ、助詞、直訳調、指示語、読点、耳で区別しにくい並列を直し、直した箇所は一覧で表示）

画面では、台本本文、検品官の判定と根拠、冒頭30秒の点数と改善案、口調・語彙の照合結果（一致度とジャンル特有の言い回し）、推敲で直した箇所が確認できます。

### 修正リスト（項目ごとに3択）

不合格になった項目（検品官・重大・冒頭30秒・口調・外部採点）は1つの修正リストにまとまり、項目ごとに次を選べます。

- **AIに直させる**：該当ブロックだけを書き直します（合格しているブロックは触りません）。一言メモを足すとAIへの指示になります。「選んだ項目をAI修正」で実行し、直したブロックの差分と再検品の結果が出ます。
- **自分で直す**：STEP 6 の添削画面に付箋として渡ります。「該当箇所へ」で編集欄の該当行に飛べます。
- **無視**：以降の検品から外れ、不合格数にも数えません。ラジオを戻せば復帰します。

「その他の修正」欄は自由記述です。書くと全体の書き直しになるので、項目で足りないときだけ使ってください。「再検品だけ」「日本語推敲だけ」も個別に押せます。不合格が残ったまま STEP 6 に進んでも構いません。

## STEP 6 添削と学習

左がAIの初稿、右があなたの手直し欄です。

1. 右側を直します。セリフ回し、語感、キャラが言わなそうな言葉、日本語のズレなど、人が見て気づく部分です。
2. 「差分を見る」で変更箇所を確認できます。
3. 「差分から学習してカルテへ」を押すと、差分から「次回から守る書き方ルール」を抽出し、固有ルールとしてカルテに入ります。同じ主旨のルールは重複登録されません。
4. 「添削の意図」欄に一言書くと、そのまま固有ルールになります（例：数字は冒頭で1回だけ）。
5. **学習したルールで残りを自動添削**：冒頭だけ手直しして学習したあと、このボタンを押すと、手直し済みの部分はそのまま残し、それより後ろにだけ固有ルールを当てて自動で添削します。直した箇所は一覧と差分で出ます。気になる箇所を追加で直して、もう一度「差分から学習」を押せば、ルールが増えて次の自動添削がさらに近づきます。

固有ルールは次回から、執筆・修正・検品・推敲のすべてに自動で注入されます。10本ほど回すと、手直しがほとんど要らない初稿に育っていきます。

## STEP 7 完了

「成功台本としてカルテに保存して完了」を押すと、手直し後の台本が `projects/<プロジェクトID>/台本.txt` に出力され、カルテに成功台本として登録されます。成功台本は文体見本として、次回の修正で「このチャンネルの声」の参照に使われます。

## 設定（右上の⚙）

- エンジン：Claude Code（本番）／モック（画面テスト用のダミー応答）
- モデル：空欄なら Claude Code の既定モデル（環境により Opus 5 など）。使えるプランなら `claude-fable-5-1` などを指定できます
- 自動検品の修正回数の上限（既定2）
- 参考台本と口調・語彙を照合する（既定オン）
- 検品合格後に日本語推敲を自動で行う（既定オン）
- 外部採点（Jev）を使う：任意。Node 22、`jev` フォルダで `npm install`、APIキーを `~/.config/jev/key.txt` に保存すると、冒頭の約束と意外性、一人称の統一、言わないことの混入、沸点の表出、メタ発言、口調の一致、ジャンル語彙、相関図との矛盾、時代背景との矛盾、プロット順の逸脱、価値観との矛盾を数値で採点し、不合格は修正の輪に入ります。無くても検品官と口調照合で同じ観点を見ます。

## 全文主義（このツールの原則）

AIに渡す材料は要約も抜粋もしません。参考台本は全文、貼り付けた素材は全文、コンセプト・キャラ・世界設定の設計書は全項目、固有ルールは全件、既に書いた本文は全文、成功台本の文体見本は全文を、該当する工程すべてに渡します。工程を分けても、分ける前より情報が減らないように作ってあります。`check_inputs.py` を実行すると、直近のプロジェクトで各工程の入力に全文が含まれているかを機械で確認できます。

例外は外部採点 Jev だけです。Jev は1回の入力に約3万2千トークンの上限があるため、参考台本は冒頭と中盤の抜粋で渡します（台本本文・キャラ・世界設定は全文）。

## データと同梱ナレッジ

すべてこのフォルダの中にあります。

- `karte/`：チャンネルカルテ。型、診断、コンセプト、キャラ、世界設定、固有ルール、成功台本、文体見本。1チャンネル1ファイル
- `projects/`：プロジェクト。参考台本、設計図、台本、検品結果、添削差分
- `knowledge/`：各工程のプロンプトに注入される資料（分析フレーム、設計図と執筆、不足検出と調査、冒頭30秒レビュー、本編構成、コンセプト正本、チャンネル6軸、コンセプト雛形、キャラクター設定、採点質問の書き方、日本語推敲基準、話し言葉仕上げ、翻訳調の検出・診断表・具体化レシピ）。編集すると次の実行から反映。画面右上「同梱ナレッジ」で閲覧できます
- `manual/`：このマニュアルと「台本の考え方マニュアル」

## うまくいかないとき

- 接続テストが失敗する：ターミナルで `claude` が起動するか確認。起動しなければ Claude Code を再インストール
- 画面が真っ白：start.bat の黒い窓のエラーを確認。多くは Python 未インストールか Flask 導入失敗
- 処理が長い：執筆は2〜4分、検品の輪を含めると10分前後かかることがあります。画面はそのままで待てます
- 検品が毎回同じ項目で落ちる：STEP 3 の固有ルールに直し方を1行足す（検品と修正の両方に効きます）
- キャラの口調がずれる：STEP 3 のキャラ設定で「言わないこと」「口癖」「文末」を具体的にする
- 日本語が硬い、AI臭い：STEP 6 で直して学習させる。数本で初稿に反映されます
