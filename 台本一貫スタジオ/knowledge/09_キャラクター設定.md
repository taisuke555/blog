# Character Bible Creator

## When to use

このスキルを使うのは、ユーザーが以下のいずれかをやろうとしているとき:

- 漫画動画用のキャラクターを設計したい
- AI画像生成でブレないキャラを作りたい
- 既存キャラの設定を整理・体系化したい
- 「キャラバイブル」「設定資料集」を作りたい

## 連携チェーン（漫画動画4スキルの流れ）

```
character-bible（本スキル：キャラ8項目固定 → characters/<name>.json登録）
   ↓ 容姿固定文字列（fixed_string）
manga-panel-scripter（30秒台本→5パネル分割。全パネルにfixed_stringを挿入）
   ↓ batch JSON
manga-image-pipeline（gpt-image-cliで画像生成・QC）
   ↓ 完成画像
youtube-thumbnail-designer（サムネ設計。主人公の容姿はここでも同じfixed_stringを使う）
```

本スキルは**起点**。ここで作るfixed_stringが下流3スキルすべての一貫性の土台になるため、曖昧な語彙（NG例参照）を残したまま次工程に渡さない。

## Core Principle: 8項目固定ルール

研究上、以下の8項目が安定すると同一人物感が一気に強くなる（GPT Image 2にはseedが無いため、言語による固定だけが再現性の担保になる）:

| # | 項目 | 例 |
|---|---|---|
| 1 | 顔型 | 面長、丸顔、卵型、逆三角形 |
| 2 | 眉 | 太い、細い、下がり眉、つり眉 |
| 3 | 目 | 奥二重、切れ長、大きめ、眠そう |
| 4 | 髪型 | 色・長さ・分け目・前髪 |
| 5 | 体型 | 細身、中肉、ふくよか、姿勢 |
| 6 | 上衣 | 色・素材・形 |
| 7 | 小道具 | バッグ、メガネ、手帳など必ず持つもの |
| 8 | 主色 | 配色のメインカラー |

## Workflow

### Step 1: ユーザーから情報を聞く

以下の順で質問する。空欄スキップ可:

**基本情報**
- キャラクター名（例: 原田典子）
- 役割（主人公/対立者/理解者/語り手）
- 年齢帯（例: 58歳）
- 性別表現
- 一言でいう性格

**容姿の固定8項目** (★最重要★)
- 顔型
- 眉
- 目
- 髪型（色・長さ・分け目・前髪）
- 体型・姿勢
- 上衣（色・素材・形）
- 小道具（必ず持つもの）
- 主色

**任意: 識別フック**
- シルエットの特徴
- 5秒で識別できるポイント

### Step 2: 容姿固定文字列を組み立てる

以下のフォーマットで自然な日本語に:

```
{年齢}歳の日本人{性別}。{顔型}。{眉}。{目}。{髪型}。{体型}。{上衣}。{小道具}。主色は{主色}。年齢感は{年齢}歳前後で固定。同じ顔立ち、同じ髪型、同じ体型、同じ服装、同じ配色を維持し、別人化しない。
```

### Step 3: gpt-image-cli に保存

`C:\Obsidian Vault\tools\gpt-image-cli\characters\<name>.json` に保存。

前提条件: Step 4以降の画像生成にはPython 3.x＋`OPENAI_API_KEY`（環境変数またはgpt-image-cliの.env）が必要。JSON登録（Step 3まで）はAPIキー不要。

CLIコマンドを使う場合:
```bash
cd "C:\Obsidian Vault\tools\gpt-image-cli"
python gpt_image.py character add <name>
```

または直接JSONファイルを作成:
```json
{
  "name": "原田典子",
  "role": "主人公の妻",
  "age_range": "61歳",
  "gender_expression": "女性",
  "personality_oneline": "控えめだが芯のある女性",
  "appearance_fixed_8": {
    "face_shape": "卵型",
    "eyebrows": "下がり眉",
    "eyes": "優しい奥二重",
    "hairstyle": "セミロング黒髪を後ろで結ぶ",
    "body_type": "中肉、姿勢はやや前傾",
    "top_wear": "薄ピンクのエプロン、白いブラウス",
    "signature_prop": "エプロン",
    "primary_color": "薄ピンクと白"
  },
  "fixed_string": "61歳の日本人女性。卵型の顔。下がり眉。優しい奥二重..."
}
```

### Step 4: 基準画像を生成

8項目を固定したら、基準画像（character sheet）を生成:

```bash
python gpt_image.py generate --template character_sheet \
  --vars CHARACTER_NAME=典子 AGE=61 GENDER=女性 \
  --vars OUTFIT="薄ピンクのエプロン、白ブラウス" \
  --vars HAIR="セミロング黒髪を後ろで結ぶ" \
  --vars FACE="卵型、下がり眉、優しい奥二重" \
  --quality medium \
  -o "characters/typical/typical_sheet.png"
```

### Step 5: 表情シート生成（基準画像の派生）

```bash
python gpt_image.py edit "Generate expression sheet: neutral, worried, angry, relieved" \
  --ref characters/typical/typical_sheet.png \
  -o characters/typical/typical_expressions.png
```

## NG例（避けるべき書き方）

❌ 「上品な女性」「地味な服」など意味語だけ
✅ 「ベージュのカーディガン」「真珠の小イヤリング」など物理的説明

❌ 「ボブ」だけ
✅ 「あご下でそろう短めの栗色ボブ、右分け」など長さ・色・分け目まで

❌ 「50代」とだけ
✅ 「58歳前後で固定。まぶたの薄さ、首の皺、姿勢のやや前傾」など年齢記号まで

## 品質ゲート（保存前セルフチェック・全✅になるまで修正してから保存する）

下流のmanga-panel-scripter／manga-image-pipelineはこのJSONを信頼して動くため、曖昧なまま保存すると全工程でキャラがブレる。

1. [ ] 8項目すべてが埋まっている（空欄スキップは基本情報のみ可、容姿8項目は不可）
2. [ ] すべて物理的説明になっている（「上品」「地味」など意味語だけの項目が無い）
3. [ ] 髪型に「色・長さ・分け目・前髪」が入っている
4. [ ] 上衣・主色に具体的な色名が入っている（「明るい色」はNG）
5. [ ] 年齢が「◯歳前後で固定」と数字で書かれている（「50代」だけはNG）
6. [ ] fixed_string が指定フォーマット（Step 2）どおりで、末尾に「別人化しない」文が入っている
7. [ ] 実在の人物名・既存キャラクター名を参照していない（権利リスクと出力不安定の両面で危険）
8. [ ] JSONがパース可能（ダブルクォートの対応・カンマ）で `characters\<name>.json` に保存された

## Input→Output ミニ例

**Input**（ユーザーの一言）: 「61歳の控えめな主婦キャラを作って。エプロン姿で」

**Output**: Step 1の質問で8項目を埋め→Step 2のフォーマットで fixed_string を組み立て（例: 「61歳の日本人女性。卵型の顔。下がり眉。優しい奥二重。セミロング黒髪を後ろで結ぶ。中肉でやや前傾。薄ピンクのエプロンに白ブラウス。主色は薄ピンクと白。年齢感は61歳前後で固定。同じ顔立ち、同じ髪型、同じ体型、同じ服装、同じ配色を維持し、別人化しない。」）→Step 3で `characters\典子.json` に保存→Step 4で基準画像を生成して確認。
