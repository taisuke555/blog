# 設計図と執筆・検品（Phase 5〜6）

## 設計図（ブロック構成表）のフォーマット

台本を書く前に必ずこれを提示する。長尺を書いてから構成をやり直すのが最大の手戻りなので、
このゲートだけは省略しない（一括モードでも「提示→そのまま執筆」はする）。

```markdown
# 台本設計図：[タイトル案]

- テーマ：[テーマ]／ターゲット：[像]／目的：[再生・リスト取り・教育]
- 総文字数目標：[◯字]（≒[◯]分）※型の尺配分に基づく
- 感情曲線：[例：不安 → 納得の積み重ね → 安心＋行動意欲]
- 適用モード：[クローン / 仮説 / 型抽出]（分析◯本ベース）

| # | ブロック | 目的 | 内容（この台本での具体） | 文字数目安 | 感情 | 適用する型 |
|---|---|---|---|---|---|---|
| 1 | フック | 離脱防止 | [例：「◯◯円」の衝撃数字→あなたも、で自分ごと化] | 150字 (5%) | ギョッとする | 型テーブル1,3 |
| 2 | ... | | | | | |

- 使用素材：[Phase 4で集めた数字・事例をどのブロックで使うか]
- 要確認：[未解決ギャップがあれば列挙]
```

対話できる文脈では、この表を見せて「ブロックの過不足・順番・配分はこれでいいか」を確認してから執筆する。
修正指示はこの表の上で受ける（台本本文の上で受けるより10倍速い）。

## 執筆ルール

1. **ブロック単位で書く。** 設計図の1行＝1ブロック。ブロックごとに文字数目安を意識し、
   書き終わるたびに実測する（全部書いてから配分崩壊に気づくのを防ぐ）。
2. **型は構造に、自由度は中身に。** 型テーブルの項目は構造（順番・配分・話法・文体）として守る。
   中身（題材・エピソード・言い回し）は自由度テーブルの範囲で新規に作る。
3. **表現コピー禁止。** 参考台本の文をそのまま・少し変えて使わない。
   目安：**連続20文字以上の一致は書き直し**。頻出フレーズ（口癖）だけは例外的に踏襲してよいが、
   それが参考チャンネル本人の台本である場合に限る（他人のチャンネルの口癖を移植すると劣化コピーになる）。
4. **数字・事実は Phase 4 の素材からのみ使う。** 出典メモを台本末尾に付ける。
5. **長尺（8,000字超）は分割執筆。** 設計図を先に固定してあるので、前半・後半を分けて書いても破綻しない。
   各分割の冒頭で直前ブロックの末尾を読み直し、接続をなめらかにする。
6. **文体の優先順位**：ユーザー指定の文体 ＞ 型テーブルの文体。
   「構成は参考台本、文体は自分」という依頼は頻出パターンなので、指定があれば型テーブルの文体行を上書きする。

## 検品（納品前に必ず実施）

### 1. 型チェックリスト照合

Phase 2で生成したチェックリストを○×表にして埋める：

```markdown
## 検品結果
| 型 | 判定 | 適用箇所・根拠 |
|---|---|---|
| 冒頭150字以内に衝撃数字フック | ○ | 冒頭「◯◯」（32字目） |
| 尺配分 フック5%/エピ30%/本編50%/CTA15% ±20% | ○ | 実測 6/28/51/15 |
| 結論後出し・後半への引っ張り | × → 修正済 | 初稿でブロック3に結論が出ていたため移動 |
```

×が出たら修正してから納品する。**どうしても型を破る判断をした場合は、破った理由を明記して残す**
（「型より事実を優先」「ユーザー指定と衝突」など。黙って破るのが一番悪い）。

### 2. 文字数実測

総文字数と各ブロックをツールで実測し、設計図の目安±20%以内か確認。超過・不足は調整。

### 3. 表現コピーチェック

参考台本と新規台本の間で、連続する長い文字列の一致が無いかを確認する。
台本が長い場合は目視でなくスクリプトで機械チェックする（Pythonで20文字窓の共通部分列を探す等）。
一致が見つかったら該当文を書き直す。

## 納品フォーマット

```markdown
# [タイトル案]（[◯]分想定・[◯]字）

## 前提（一括モード時のみ：採った判断の列挙）
## 台本本文
[ブロック見出し付きで本文]
## 検品結果
[○×表＋文字数実測＋コピーチェック結果]
## 出典メモ
[使用した数字・事例の出典]
## 要確認リスト
[未解決の [要確認] マーカー一覧（あれば）]
```

納品後、ユーザーの修正フィードバックはカルテ（`karte/`）に追記する。
「この型は外していい」「この言い回しは好み」のような学習が次回の精度になる。
