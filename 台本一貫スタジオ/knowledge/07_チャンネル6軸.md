# チャンネル版6軸｜判定基準（◎○△×）と落とし穴

> 採点・セルフ採点で記号に迷ったらここ。別の評価者が同じ記号を再現できる粒度で判定する。
> 骨格は南幅式6軸（正本：`🎯_企画コンセプト設計\企画コンセプト設計_正本_南幅式.md`）、中身はN式チャンネル設計（`YouTube\N式_YouTubeリストマーケ講座\ナレッジ\01_N式_チャンネル設計ナレッジ.md`）。

## ① 市場があるか（足切り）

| 記号 | 基準 |
|---|---|
| ◎ | 同ジャンルで登録者比の伸び率が高い競合が複数あり、かつ飽和しきっていない（後発の入る隙＝ずらし余地が言える） |
| ○ | 伸びている競合が1〜2ある。需要は証明済みだが王道は取られている |
| △ | 隣接ジャンルには需要があるが、この柱の組み合わせそのものの前例がない（仮説扱い。テスト設計を条件に通す） |
| × | 伸びている競合が見つからない／需要の根拠が「自分が見たいから」しかない |

**落とし穴**：競合ゼロを「ブルーオーシャン」と加点しない。YouTubeでは競合ゼロ≒需要ゼロが第一仮説。逆に、競合が多いことは×ではない（需要の証明）。×は「差別化不能」のときだけで、それは④で見る。

## ② 登録動機があるか（足切り）

| 記号 | 基準 |
|---|---|
| ◎ | 「また見たい」の理由が1行で言え、柱がシリーズ性を持つ（続きを見たくなる構造）。チャンネルの約束が明文化されている |
| ○ | 約束は言えるが、単発でも成立する動画の集合に近い（登録より単発視聴で消費されやすい） |
| △ | 良い動画は作れそうだが「なぜこのチャンネルを登録するのか」に答えられない |
| × | 一発ネタ・雑多な寄せ集めで、視聴者から見て「何のチャンネルか」が定まらない |

**落とし穴**：「役に立つから登録される」は理由になっていない（役に立つ動画は単発消費される）。登録動機＝**次も・全部見たい理由**。

## ③ 商品・リストに接続できるか（足切り）

| 記号 | 基準 |
|---|---|
| ◎ | 視聴者層＝商品が売れる層で、演者ポジション（高単価＝先生／低単価＝共感）が単価と一致。リスト移行の導線（特典・CTA）まで柱に織り込める |
| ○ | 層は合っているがポジション設計に弱点（例：高単価なのに権威の見せ場が柱にない） |
| △ | 集まる視聴者と買う層が半分ズレる（例：ノウハウ乞食層が集まる柱構成で高単価商品） |
| × | 高単価×見下されるキャラ設計／視聴者層と購入層が別人種／売る商品が決まっていないのに柱だけ決めようとしている |

**落とし穴（N式03）**：教えたがりコメントが大量につく設計＝視聴者が演者を下に見ている兆候。ファンが増えても高単価は売れない。女性演者×男性視聴者は特に権威性を意図的に設計する。

## ④ キャラ・世界観で差別化できているか（売上）

| 記号 | 基準 |
|---|---|
| ◎ | 10秒テスト合格＋99人一致テスト合格＋見下せるポイント1つあり＋世界観は競合準拠で、差別化がキャラ・権威・情報量のどれかで具体的に言える |
| ○ | 印象は揃うが、競合と並んだとき「この人を選ぶ理由」が弱い |
| △ | キャラ要素は列挙されているが視聴者に見える形（3チャネル）に落ちていない＝設定を置いただけ |
| × | 完璧キャラ（隙ゼロ）／ゼロイチの独自世界観を差別化と呼んでいる／演者が続けられない盛り方 |

**落とし穴**：世界観の独自性は差別化ではない（競合に寄せるのが正。N式02）。差別化の置き場は演者キャラ・権威性・情報量の3つに限定して評価する。

## ⑤ 投稿の柱で約束を回収・量産できるか（売上）

| 記号 | 基準 |
|---|---|
| ◎ | 柱3〜5本に役割（集客/教育/信頼）が割れ、各柱10本先までネタが言え、疑似体験装置があり、制作リソース内で回る |
| ○ | 柱と役割はあるがネタの持続性か制作リソースのどちらかに不安 |
| △ | 柱が実質1本（それが外れたら終わり）／疑似体験なしの情報羅列（潜在ニーズ商品なら重い減点） |
| × | 約束と柱が別物（入口で約束したものを動画が回収しない）／月間制作可能本数で物理的に回らない |

**落とし穴**：④⑤はペア。強い約束・強いキャラほど柱の中身（情報優位性・疑似体験）が重くなる。④◎×⑤△は加点にせず〈期待倒れリスク〉として両論併記。土台は情報優位性、キャラはアクセント（N式04）。

## ⑥ 前に出す1つが絞れているか（仕上げ）

| 記号 | 基準 |
|---|---|
| ◎ | チャンネル名・タグライン・サムネの型が1つの期待に絞れ、集まる層まで言える |
| ○ | 絞れているが、その1つで①〜⑤の連動を確認していない |
| △ | 2つ以上を前に出している（全部盛り名・肩書き列挙） |
| × | 前出し未設計（中身はあるが入口が決まっていない） |

**落とし穴**：何を前に出すかで集まる層が180度変わる。迷ったら⑥を動かして①〜⑤の連動を見る（南幅式の黄金パターン）。

# 設計シート → チャンネルカルテ マッピング表

生成モード完走時、設計シートから `C:\Obsidian Vault\企画分析\カルテ\<チャンネル名>.md` へ以下を転記する（カルテ形式の正本＝youtube-kikaku-radar `templates/karte-template.md`）。

| カルテ項目 | 設計シートの出どころ |
|---|---|
| 基本情報 ★（チャンネル名/ジャンル/属人・非属人） | ステップ7（名前）＋前提ヒアリング。新規はURL・登録者数は空欄で「未開設」と明記 |
| 核コンセプト ★ | 設計シートの約束＋前出し（1〜3行：誰に・何を・どんな立ち位置で） |
| ターゲット像 ★ | ステップ5（集める層。悩みの表面と深層まで） |
| チャンネルの約束 ★ | ステップ4（登録動機。破ってはいけないことも1行） |
| キャラクター・文体 | ステップ6（キャラ＋3チャネルのバーバル部分。絶対に使わない表現＝NG口調） |
| 競合チャンネル ★ | ステップ6で寄せ先にした競合＋①の需要証明に使った競合（2〜5個） |
| 市場の王道/飽和パターン | ①②の分析から分かった範囲で |
| 視聴者基準値・勝ちパターン・レンズ別打率・企画履歴 | **空の器で置く**（kikaku-radarが実行のたびに育てる領域。勝手に埋めない） |
| 制作リソース | 前提ヒアリング⑤（月間本数・形式・運営NG） |

**注意**：カルテの既存ファイルがある場合（リブランド時）は上書きせず、変更点を差分で提示して合意後に更新する。
